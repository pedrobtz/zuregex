# zuregex bug hunt, 2026-11-16

Commit `c9acf70`. Hunters: 3 on Fable, run one at a time. Slices: the R
layer; matching semantics against reference engines; lifecycle, ownership
and the C API. Coordinator on Opus 5.5. Built here: macOS x86-64, R 4.6,
JIT on, without OpenMP. Hunter 3 also built the C core, and the whole
package, under ASan and UBSan.
Unverified: OpenMP phase 2 and thread-count independence; Windows; Linux;
ThreadSanitizer; allocation failure; non-UTF-8 multibyte locales; a
platform without a usable JIT.

This hunt was the behaviour pass of a critical review. The code pass found
the JIT-stack defect independently. Every reproduced trigger was re-run
by the coordinator against a fresh install of the pinned commit. Scripts
are in `2026-11-16-bug-hunt-probes/`; `consolidation/` holds the re-runs.

## 1. Give phase 2 a JIT stack so default calls do not fail at about 1 KB — #166, high, reproduced

- Where: `src/match.c:391-398`; no `pcre2_jit_stack_create()` in `src/`.
- Trigger: `re_detect(strrep("ab", 512), "^(a|b)*$")` raises
  `zuregex_error_limit` (`jit_stack`). `grepl(perl = TRUE)` and
  `jit = FALSE` both return `TRUE`. Ordinary patterns fail from 1 to
  16 KB.
- Cause: the JIT runs on PCRE2's built-in 32 KiB stack, and no limit
  raises it.
- Fix: a per-thread JIT stack, or an interpreter retry on
  `PCRE2_ERROR_JIT_STACKLIMIT`.
- Family: 4. Design §4 lists "JIT stack per thread"; only half was built.
  Siblings checked: every verb, the fast and general paths.
- Test the suite lacked: perl parity on 1, 4 and 64 KB subjects with
  repetition patterns.

## 2. Match variable-length lookbehinds with the interpreter until PCRE2's JIT agrees — #167, high, reproduced

- Where: `src/match.c:391-397`; the cause is upstream PCRE2 10.49's JIT.
- Trigger: `re_detect("ab", "a(?<=a(?=b)c?)b")` is `FALSE` under JIT.
  It is `TRUE` with `jit = FALSE`, with `anchor = "start"`, and in
  `grepl()`. `(?<=\R)\n` on `"\r\n"` differs the other way. A fuzz found
  127 differences in 6,762 cases.
- Fix: report it upstream; until then, fall back to the interpreter.
- Family: none of the four. See Cross-cutting.
- Test the suite lacked: a JIT-against-interpreter differential (#50,
  #136).

## 3. Clear live patterns and the cache when the DLL unloads — #168, high, reproduced

- Trigger: `keep <- re_compile("x")`, unload the namespace, then
  `library.dynam.unload()`, `rm(keep)` and `gc()`. R segfaults; the ASan
  build does too.
- Cause: the C finalizer points into the unmapped DLL, and there is no
  unload hook.
- Family: 2. Siblings: cache slots, preserved strings.
- Test the suite lacked: unload, `gc()`, then reload.

## 4. A foreign external pointer in an re object is dereferenced — #159, high, reproduced

- This was already filed by the assurance audit and was rediscovered here.
- Trigger: put a `textConnection()`'s pointer into an `re`, then call
  `re_info()`. R segfaults.
- Family: 3. Every reader of the pointer checks only its type.

## 5. The remaining medium findings

Each is reproduced and filed with its trigger:

- **#169:** `re_info()` prefix and `min_length` are wrong under `\K`,
  `(?#…)`, `\Q…\E` and `\c`.
- **#170:** a compile error names the de-duplicated table's index.
- **#171:** `re_escape()` is not literal under `js` or on bytes, and gives
  `<ff>` in a C locale.
- **#172:** `OutDec = ","` breaks `print(re_limits())` and declasses an
  error.
- **#173:** a latin1 string does not match itself in bytes mode.
- **#174:** `re` methods return a broken or declassed object.
- **#175:** a replacement function's strings skip the template checks.
- **#176:** an edited or capped `re` answers differently for raw subjects.
- **#177:** the C API's match data goes stale or is sized wrong.
- **#131** (comment): invalid UTF-8 and bytes patterns and templates
  give unclassed errors.
- **#46** (comment): an unnamed `proto`.
- **#164** (comment): the `zr_substitute()` buffer contract.

Low: #178, which covers documentation errors and `group = 2^31`.

## Cross-cutting

- **Defects in the default configuration.** The JIT is the default, and
  the suite compares it only with itself. Two of the three high findings
  live there. Candidate rule for `correctness.md`: *a package with two
  engines for one result (JIT and interpreter, fast and slow path,
  native and fallback) runs a differential between them on the
  conformance corpus.* The fast/general differential in
  `test-prepare.R` is why that pair held.
- **Representation, not value.** Several findings are one object
  answering differently by route: character against raw (#173, #176),
  pointer against attributes (#176), user index against table index
  (#170).
- **Escape hatches of R itself.** `nchar()`, `format(big.mark =)`,
  `as.integer()` and method dispatch defaults (`$<-`, `unique()`) all
  turned user input into unclassed errors or broken objects.

## Held: what was probed and stood

- **Python `re` differential:** 28,000 random cases over iteration,
  offsets, captures, split, replace and `n`. Only known engine
  differences.
- **Base R `perl = TRUE`:** 30,000 cases, 0 mismatches.
- **Python `regex` with `overlapped=True`:** 12,000 cases, 0 mismatches.
- **Anchoring:** 12,000 cases against `match` and `fullmatch`, 0
  mismatches.
- **JS dialect against node 22:** about 26,000 cases. Iteration agrees.
  The differences are filed (#163).
- **Templates:** about 13,000 against `pcre2test`, and 4,000 against
  Python's `expand()`. 0 mismatches.
- **Flags against inline options:** 60,000 checks.
- **Routes:** 21 verb variants × 12 patterns × 6 subject sets, under
  hostile options and locales. Identical.
- **Limits:** the exact `match` boundary on all 11 verbs; `on_limit =
  "na"`.
- **Cache:** LRU order, eviction, key separation, and the 65,536
  character boundary for UTF-8 patterns.
- **Lifecycle:** 4,000 random operations on the ASan build against
  `grepl()`; fork with open objects; replacement functions that clear
  the cache. No mismatch and no report.
- **C API:** `errbuf` sizes, NULL handles, group bounds, start offsets,
  match data from another pattern, and 8 threads sharing a pattern under
  ASan.

## Not reached

- OpenMP builds and ThreadSanitizer.
- Allocation-failure paths.
- Subjects near 2^31 bytes.
- Windows, and non-UTF-8 multibyte locales.
- stringr parity: base R, Python, node and `pcre2test` were used instead.
- The consumer fixture.

## Not reproduced, and by design

- **Duplicate group names give one `re_match()` column.** By design
  (#76); the docs need to say so (#187).
- **`\0` in a template is an octal NUL.** This is PCRE2's syntax; `$0` is
  the whole match.
- **The nightly fuzz OOM.** Fixed by #133 (#128); a fuzz run on `c9acf70`
  was dispatched to confirm.
